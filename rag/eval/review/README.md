# Reviewing the 43 evaluation queries

Files: `review_sheet.csv` (fill this in; opens in Excel/LibreOffice/Google Sheets) and `review_sheet.md`
(the same content, easier to read). Both were generated by `python rag/review.py export` from the frozen
`eval/queries.jsonl` (14 ESCO, 25 job-description, 4 no-answer queries).

## What each row shows

| Column | Meaning |
|---|---|
| `qid`, `source_type`, `lang`, `query` | The question as asked to the RAG |
| `expected_answer` | ESCO: the expected concept label(s). Job: the gold quote. No-answer: `no_match` |
| `gold` | What the metric counts as correct. ESCO: concept URI(s), separated by ` \| `. Job: verbatim quote(s), separated by ` \|\| ` |
| `supporting_passage` | ESCO: the concept's full entry. Job: the gold quote marked `[[ ]]` with 200 characters of context |
| `source_reference` | ESCO version, or posting title, agency, USAJOBS URL and how often the quote occurs |
| `alternative_candidates` | Top-3 results of the default system (structure chunking, e5-small dense) that are **not** gold. System suggestions, not verified: use them to spot answers that are also correct |
| `decision` | **Fill in**: `ACCEPT`, `CORRECT` or `REJECT` |
| `corrected_gold` | **Fill in only for CORRECT**: the complete new gold list, same format as `gold`. To add an alternative, copy the old gold and append the new one |
| `notes` | **Fill in**: free text, e.g. why a query is ambiguous |

Decision guide:
- **ACCEPT**: the query is clear and the gold is a correct, sufficient answer.
- **CORRECT**: the query is fine but the gold is wrong or incomplete (e.g. E04: "operate relational database
  management system" may also be correct). Job quotes must be copied **verbatim** from the posting.
- **REJECT**: the query is ambiguous or unanswerable as written (e.g. a global query that every posting answers).
  Rejected queries are dropped from the reviewed set, not edited.

## Applying your review (nothing is overwritten)

1. Save the filled sheet as `rag/eval/review/review_sheet.csv` (keep the header row and the `qid` column).
2. Run `python rag/review.py apply --reviewer "Your Name"`.
   - Every row must have a valid decision, and every corrected gold must be an ESCO URI from our subset or a
     verbatim quote from the posting. If any row fails, **nothing is written** and the errors are listed.
   - Output: `eval/queries_reviewed.jsonl`, with `verified_by`, `review_decision`, `review_notes`, and for
     CORRECT rows the previous gold kept as `gold_original_uris` / `gold_original_quotes`.
   - Output: `eval/review/changelog.md`, one line per query: decision, old gold, new gold, notes.
3. Re-run the evaluation on the reviewed set:
   `HF_HOME=<cache> CUDA_VISIBLE_DEVICES= python rag/evaluate.py --queries rag/eval/queries_reviewed.jsonl --models e5-small bge-m3`
   Results go to `eval/results_queries_reviewed/`. The original `eval/queries.jsonl` and `eval/results/` stay
   unchanged, so the report can show both the AI-drafted and the human-verified numbers.
4. Commit the sheet, `queries_reviewed.jsonl`, `changelog.md` and the new results together.
