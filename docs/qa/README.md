# HireSignal QA (Session 5)

| suite | what | backend | when |
|---|---|---|---|
| `tests/qa/` | contracts (frozen v1), grounding, false-MET traps, citations and RAG relevance, prompt injection, Judge, Bias Auditor, fallback and robustness | **MOCK**: scripted answers, stub HTTP servers, keyword NLI stand-in | always (window 0 safe) |
| `tests/live/` | the same contracts on the real LoRA and base Matcher: trap probes, positive controls, verbatim spans, determinism, provenance, real fallback, counterfactual flags, Judge (opt-in) | **LIVE** | skipped unless `HS_LIVE=1` and the servers answer (window 1) |

Mock success is not live-model validation. A green `tests/qa` says the deterministic code enforces the contracts
when it receives a given model answer. It says nothing about how often the real model produces such answers.

## Run

```bash
tests/qa/run_qa.sh                 # mock: matcher + benchmark tests + tests/qa; summary -> docs/qa/last_run_mock.txt
HS_LIVE=1 HS_MATCHER_URL=http://127.0.0.1:8081/v1 HS_FALLBACK_URL=http://127.0.0.1:8080/v1 \
  HIRESIGNAL_RAG_DIR=<rag> HS_RAG=bm25 HS_LIVE_OUT=docs/qa/live_runs/<run-id> tests/qa/run_qa.sh --live
#   add HS_LIVE_JUDGE=1 to load the NLI Judge
```

The live run writes `provenance.json` (servers' `/models`, `backend.info()`, knowledge provider, judge, git commit,
`HS_*` env without secrets) and `results.jsonl` (raw model text plus the validated row per probe, labelled `LIVE`).
Cite that directory for any live claim. The harness was self-tested against a stub server that answers with the
lexical baseline (MOCK, not committed). It runs end to end and fails on the negation and years traps, as expected
until QA-002 and QA-004 are fixed.

## Markers

`defect("QA-xxx", owner)` is a strict xfail that reproduces an open defect in `FAILURES.md`. When a fix lands, the
test XPASSes and the run fails until the marker is removed. That is intended: the test stays as a regression test.
